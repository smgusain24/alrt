    **Structure:**
    ```python
    import json, logging, os, uuid
    import httpx
    from alrt_workers.celery_app import celery_app
    from alrt_workers.db import execute_read_one_query, execute_insert_query, execute_update_query
    from alrt_workers.utils.crypto import get_fernet
    from alrt_workers.utils.retry import DISCORD_RETRY
    from alrt_workers.utils.template import render
    ```

    **Queries** (module-level constants, same pattern as email.py):
    - `Q_GET_SUBSCRIBER`: SELECT with `discord_webhook_url` included in the column list. Full list: `id, team_id, external_id, email, name, slack_user_id, phone_number, discord_webhook_url, telegram_chat_id, custom_properties, channel_preferences`
    - `Q_GET_DISCORD_PROVIDER`: `SELECT id, team_id, channel, provider_type, config, is_active FROM providers WHERE team_id = $1 AND channel = 'discord' AND is_active = true LIMIT 1`
    - `Q_GET_NOTIFICATION`, `Q_CREATE_NOTIFICATION` (channel='discord'), `Q_MARK_SENT`, `Q_MARK_FAILED`, `Q_MARK_DEAD_LETTER`, `Q_GET_TEMPLATE` — same as email.py but with channel='discord'

    **`PERMANENT_HTTP_CODES = {400, 401, 403, 404}`** (404 = webhook deleted)

    **`class _PermanentDiscordError(Exception): pass`**

    **`deliver()` function:**
    1. Get subscriber — check for `discord_webhook_url` on subscriber first
    2. If no subscriber-level URL, check team provider for fallback: `Q_GET_DISCORD_PROVIDER` → `config.get("webhook_url")`
    3. If provider is alrt_hosted: decrypt config with fernet, extract `webhook_url`
    4. If neither has a URL, log warning and return
    5. Resolve template_id (same pattern as email.py)
    6. Render title via `render(template_data.get("title", ""), payload, subscriber)`
    7. Render body/description via `render(template_data.get("body", template_data.get("text", "")), payload, subscriber)`
    8. Create notification row (if not retry)
    9. Call `_send_discord_message()` — on success, mark sent + quota increment
    10. Handle `_PermanentDiscordError` → DLQ immediately
    11. Handle general exceptions → retry with kwargs or DLQ on max retries (same pattern as email.py)

    **`_send_discord_message(webhook_url, title, description, color_hex, footer, timestamp)` helper:**
    - Convert `color_hex` to int: `int(color_hex.lstrip("#"), 16)`. Default color: `"3b82f6"` (blue).
    - Build embed dict: `{"title": title[:256], "description": description[:4096], "color": color_int}`
    - If footer: `embed["footer"] = {"text": footer[:2048]}`
    - If timestamp: `embed["timestamp"] = timestamp` (ISO 8601)
    - POST to `webhook_url` with `json={"embeds": [embed]}`, timeout=10
    - Check response: if `status_code not in (200, 204)` → `_check_response(resp)`

    **`_check_response(resp)` helper** (same pattern as email.py):
    - If `resp.status_code in PERMANENT_HTTP_CODES`: raise `_PermanentDiscordError`
    - Else: `resp.raise_for_status()`

    **Template data fields for Discord** (extracted from workflow node config):
    - `template_data.get("title")` → embed title
    - `template_data.get("body")` or `template_data.get("text")` → embed description
    - `template_data.get("color", "3b82f6")` → embed color (hex string, converted to int)
    - `template_data.get("footer", "")` → embed footer text
    - `template_data.get("embed_enabled", True)` → if False, send plain content instead of embed

    If `embed_enabled` is False, POST `json={"content": description[:2000]}` instead of embeds.

    **Mention passthrough:** Discord mention syntax like `<@user_id>` and `<@&role_id>` in the body is passed through as-is — no special handling needed per user decision.

    Create `apps/workers/alrt_workers/tasks/channels/telegram.py` following the same worker pattern.

    **Structure** (same imports as discord.py):
    ```python
    import json, logging, os, uuid
    import httpx
    from alrt_workers.celery_app import celery_app
    from alrt_workers.db import execute_read_one_query, execute_insert_query, execute_update_query
    from alrt_workers.utils.retry import TELEGRAM_RETRY
    from alrt_workers.utils.template import render
    ```

    **API constant:**
    ```python
    TELEGRAM_API_URL = "https://api.telegram.org/bot{token}/sendMessage"
    ```

    **Queries** (module-level, same pattern):
    - `Q_GET_SUBSCRIBER`: same full column list including `telegram_chat_id`
    - `Q_GET_NOTIFICATION`, `Q_CREATE_NOTIFICATION` (channel='telegram'), `Q_MARK_SENT`, `Q_MARK_FAILED`, `Q_MARK_DEAD_LETTER`, `Q_GET_TEMPLATE`
    - No provider query needed — Telegram uses shared bot token from env (`TELEGRAM_BOT_TOKEN`)

    **`PERMANENT_HTTP_CODES = {400, 401, 403}`**
    - 400 = bad request (invalid chat_id, malformed message)
    - 401 = unauthorized (invalid bot token)
    - 403 = forbidden (bot blocked by user/group)

    **`class _PermanentTelegramError(Exception): pass`**

    **`deliver()` function:**
    1. Get subscriber — check for `telegram_chat_id`
    2. If no `telegram_chat_id`, log warning and return
    3. Get bot token from env: `os.getenv("TELEGRAM_BOT_TOKEN", "")`. If empty, log error and return.
    4. Resolve template_id (same pattern)
    5. Render body via `render(template_data.get("body", template_data.get("text", "")), payload, subscriber)`
    6. Determine parse_mode: `template_data.get("parse_mode", "Markdown")` — use legacy Markdown, NOT MarkdownV2 (per research recommendation: MarkdownV2 escape logic is subtle; legacy is forgiving)
    7. Create notification row (if not retry)
    8. Call `_send_telegram_message()` — on success, mark sent + quota increment
    9. On `_PermanentTelegramError` → DLQ
    10. On general exception: if 429 (rate limited), extract `retry_after` from response and use as countdown: `raise self.retry(countdown=retry_after, ...)`; otherwise standard retry/DLQ pattern

    **`_send_telegram_message(token, chat_id, text, parse_mode)` helper:**
    ```python
    resp = httpx.post(
        TELEGRAM_API_URL.format(token=token),
        json={
            "chat_id": chat_id,
            "text": text[:4096],  # Telegram limit
            "parse_mode": parse_mode,
        },
        timeout=10,
    )
    ```
    - If `resp.status_code == 429`: extract `retry_after = resp.json().get("parameters", {}).get("retry_after", 5)`, raise `_TelegramRateLimited(retry_after)` (a custom exception the deliver function handles by calling `self.retry(countdown=retry_after)`)
    - If `resp.status_code in PERMANENT_HTTP_CODES`: raise `_PermanentTelegramError`
    - Otherwise: `resp.raise_for_status()`
    - Also check `resp.json().get("ok")` is True; if not, raise with the error description

    **`class _TelegramRateLimited(Exception):`** — stores `retry_after` as attribute for the deliver function to use

    **Template data fields for Telegram:**
    - `template_data.get("body")` or `template_data.get("text")` → message text
    - `template_data.get("parse_mode", "Markdown")` → Markdown or HTML
